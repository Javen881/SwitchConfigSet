# SwitchBatchCLI 项目启动文档

版本：0.1 · 日期：2026-11-02 · 状态：需求基线与实施草案，尚未开发或连接设备。

## 1. 项目目标与范围

建立本地桌面工具：用户提供设备 IP/网段和命令，通过 SSH/Telnet 批量下发，实时查看过程，完整保存配置命令及查询命令的设备回显，按任务批量导出。

核心原则：不丢命令、不丢已接收回显、不丢执行过程。查询得到的版本、接口、VLAN、MAC、生成树、日志、配置等信息均为正式交付数据，不仅是界面临时显示。超时或断连必须保留部分回显并标记不完整。此原则是实现及验收目标，不承诺断电前尚未落盘的数据绝对无损。

目录名中的 CLI 指交换机命令行接口；第一版按此前方案规划桌面 GUI，并不表示只开发命令行程序。

原任务曾提出所有设备出厂 IP 相同、按 MAC 修改配置。该需求保留为前置初始化方向：本版批量连接要求每个目标已有唯一且可达的管理 IP。不能用普通 IP 扫描或 ARP 表可靠区分同 IP 的多台设备。厂家二层定向修改协议尚未确认；若后续需要，单独验证厂家工具/协议，或采用逐台接入、逐端口隔离初始化。此能力不作为本版已经具备的功能。

## 3. 第一版功能边界

| 纳入第一版 | 说明 |
|---|---|
| 单 IP、IP 列表、CIDR | 支持粘贴或 TXT 导入、校验、去重和展开预览 |
| SSH/Telnet 与端口探测 | 可配置端口；展示探测结果后选目标，探测不直接触发命令 |
| 手工命令与 TXT 导入 | 一行一条，保留顺序及原文；预览最终发送清单 |
| 多设备并发 | 设备之间受限并发；同设备单会话串行执行 |
| 实时显示 | 当前命令、发送/接收事件、每台设备状态、进度 |
| 统一执行和信息采集 | 配置/查询/其他只是标记，均完整记录 |
| 独立日志和历史任务 | 逐任务、逐设备、逐命令可追溯 |
| TXT/CSV/JSON 与 ZIP | 原始回显、配置查询输出、汇总、记录整体导出 |
| 中断处理 | 超时、断连、取消、程序异常保留已落盘内容并明确状态 |

暂不做：AI 诊断、拓扑管理、自动配置模板库、协议自动判定、抓包/流量发生器集成、厂家二层改 IP、自动回滚、自动保存设备配置、跨设备多阶段编排、任务运行中随意插入命令。不同设备需要不同命令时，第一版可分批建立任务；设备到命令文件映射列为待确认扩展。

## 4. 操作流程

输入 IP/列表/CIDR → 校验并预览展开目标 → 探测指定 SSH/Telnet 端口 → 勾选目标及连接参数 → 手工输入/导入 TXT → 标记命令类型并预览顺序 → 确认目标和命令 → 创建任务及日志 → 并发连接、逐设备串行发送 → 实时落盘与显示 → 汇总完整/不完整/失败结果 → 查看历史或导出 ZIP。

配置和查询可以混排，保留 CLI 上下文。不同厂商命令不自动翻译。进入配置模式、退出、保存及回读命令均需明确列出；适配器若自动发送取消分页等辅助命令，也必须记录。连接失败应形成设备记录，未发送命令显示“未执行”。

## 5. IP 与网段输入

第一版建议先实现 IPv4；IPv6、起止 IP 范围为待确认项，不因历史建议自动扩大范围。支持换行或逗号分隔的单 IP/CIDR 混合输入，例如：

```text
192.168.10.10
192.168.10.20,192.168.10.21
192.168.20.0/24
```

解析规则：拒绝无效地址；去重但保留输入来源；CIDR 有主机位时提示规范网段并展示，不静默扩大；常规 IPv4 子网排除网络/广播地址，/31 与 /32 按可用端点语义处理。设置展开数量上限并先计数再枚举，大网段不得无界扫描。建议初值最多 1024 个地址、探测并发 32、执行并发 5，均待小规模验证后调整。

探测默认候选端口为 SSH 22、Telnet 23，可修改。TCP 端口开放不代表登录成功或目标一定是交换机；不以 Ping 失败直接排除设备。先展示 IP/端口/协议候选/探测状态，用户选择后再执行。

## 6. SSH/Telnet 与会话执行

SSH 优先；Telnet 由用户明确选择，不在 SSH 认证失败后静默降级。认证信息运行时输入，登录密码/私钥不写普通事件日志或 ZIP；SSH 主机密钥变化应可见。Telnet 无加密属性应在协议选择处说明。

各设备配置协议、端口、账户、设备类型、回显编码、连接/命令超时。第一版品牌适配范围待确认，不承诺通用适配所有交换机。发送前持久化意图，发送后持续读流；按提示符、分页与交互状态判断完成，不能只依赖固定 sleep。未知确认提示停止该设备后续队列并记录原因，不盲目发送 yes。

命令错误默认停止该设备后续命令，其他设备继续；配置命令超时不自动重发，避免重复副作用。取消停止排队及后续发送，保留当前命令已收内容，并标记设备侧是否执行完成未知。修改管理 IP 导致掉线不能直接记为成功；自动新地址重连不作为本版既定功能。

## 7. 命令执行与原始回显留痕模型

层次：任务 Task → 设备执行 DeviceRun → 命令执行 CommandRun → 收发事件 IOEvent。每次尝试使用独立 ID；重复命令也以序号区分，不以命令字符串作唯一键。

| 记录 | 必需字段 |
|---|---|
| Task | task_id、创建/开始/结束时间、时区、输入目标快照、确认目标、命令文件/清单快照、执行参数、状态、可选关联用例 |
| DeviceRun | device_run_id、task_id、IP、协议、端口、设备类型、可选型号/固件、连接起止、认证结果、错误、日志路径 |
| CommandRun | command_run_id、device_run_id、序号、命令原文、类型（配置/查询/其他）、来源行号、发送/结束时间、耗时、执行状态、判定依据、错误、完整性、回显路径及字节范围 |
| IOEvent | 单调递增序号、时间、设备/命令关联、方向（TX/RX/系统事件）、块位置与长度、辅助交互标记 |

时间使用带时区的 ISO 8601（毫秒精度），耗时使用单调时钟。状态至少包含：排队、运行、完成、设备报错、超时、断连、取消、未执行、未知；另存 `output_complete` 和 `incomplete_reason`。无错误提示只说明执行流程完成；业务验证默认“未验证”，不伪造配置成功结论。

### 原始数据和可读记录

- 原始回显指 SSH 解密后/Telnet 协议处理后的 CLI 接收流，不是网络抓包。尽量在适配器去提示符、去命令回显、清理 ANSI 之前捕获；实现阶段验证库接口是否满足，必要时增加底层读取钩子。
- 原始字节或可逆编码块追加保存；另生成 UTF-8 可读 TXT。分页标记、提示符、设备回显命令和控制字符不从原始文件删除；界面可清理显示，但不覆盖原始数据。
- 流式接收并增量落盘，界面仅保留有限窗口；不得只在命令返回后一次性保存。断连、超时和日志写入失败均有异常路径；落盘失败应停止新命令并明确告警，不能显示“完整留痕成功”。
- 不伪造未收到的信息。程序重启时将遗留运行任务标记“中断/待核对”，不自动续发配置。
- 登录认证秘密不进入常规日志；用户配置命令及设备配置回显本身可能包含敏感内容。原始证据受本地访问权限保护；如需脱敏导出，生成独立副本并注明，不能静默更改原始证据。

## 8. 实时界面与日志目录

界面建议：目标导入区、命令编辑/预览区、设备执行列表、当前设备实时终端区、任务历史及导出入口。每行显示 IP、协议、当前命令序号、状态和错误；终端区区分发送、接收、系统事件。后台通过信号传递流片段，界面不承担网络阻塞操作。

计划运行数据结构（本次仅创建文档，不生成运行日志）：

```text
SwitchBatchCLI/
  README.md
  data/tasks.sqlite3
  logs/<日期>/<task_id>/
    task.json                 # 任务及参数快照，不含登录秘密
    commands.txt              # 确认后的命令清单
    summary.csv               # 一行一设备，含完成/失败/未执行数量
    command_results.jsonl     # 逐命令结构化结果
    events.jsonl              # 连接、异常、收发索引等事件
    devices/<device_run_id>/
      session.rx.bin          # 完整 CLI 接收流
      transcript.txt          # 带时间与命令的可读过程
      commands/000001.txt     # 单条命令可读回显
      collected/              # 查询配置等输出副本，关联命令 ID
  exports/<task_id>.zip
```

任务 ID 使用时间加随机唯一后缀；文件名由内部 ID 生成，避免设备文本成为路径。每台设备独立文件，任务内唯一编号，历史数据禁止覆盖。配置查询导出是收到的查询输出，并不保证是可直接恢复到设备的配置文件。

ZIP 包含任务快照、设备日志、查询输出、逐命令记录、汇总和导出清单（相对路径、大小、SHA-256）；不打包认证材料。JSON/JSONL 是可移植完整记录，SQLite 为本地索引，不直接复制正在写入的数据库。默认在任务结束后导出；运行中导出必须标记快照时间与不完整状态。完成后验证可解压、路径安全和清单一致性；CSV 使用标准转义，并处理电子表格公式触发前缀，命令原文仍以 JSON/原始日志为准。

## 11. 实施计划与验收

| 阶段 | 工作 | 验收出口 |
|---|---|---|
| P0 需求与准备 | 本文、设备资料收集、选定首个型号、确认开发环境 | 核心范围和未决项可追踪，旧资料不被覆盖 |
| P1 记录基础 | IP 解析、任务/设备/命令模型、流式日志、模拟适配器 | 重复命令、无效输入、大网段、超时部分回显均能正确记录 |
| P2 单设备引擎 | SSH/Telnet、提示符/分页/交互、错误与超时 | 每种协议验证长输出、多页、中文及断连；已接收内容可恢复查看 |
| P3 批量与 GUI | 受限并发、实时显示、取消、历史任务 | 单设备严格按序，多设备不串日志；慢设备不冻结界面 |
| P4 导出与恢复 | TXT/CSV/JSON/ZIP、运行中断标记 | ZIP 解压及清单校验通过，数量与数据库/日志一致 |
| P5 实机小批验证 | 先查询后在测试设备执行明确配置及回读 | 同批查询和配置均留痕，命令完成与功能通过分别呈现 |

关键验收场景：

1. 同一设备依次执行配置、版本查询、接口查询，每条命令有独立记录，查询信息不会被后续输出覆盖。
2. 长输出超过界面显示窗口，磁盘原始流仍完整；分页处理可追溯，导出可读取全部内容。
3. 第三条命令超时或断连，前两条记录完好，第三条部分输出保留并标不完整，后续命令标未执行。
4. 认证失败、语法错误、未知确认、主动取消和磁盘写失败各有真实状态，不统一误报成功。
5. 多台设备并发不混日志；重启后历史任务仍可查看，中断任务不自动重放。
